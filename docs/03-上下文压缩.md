# 03 · 上下文压缩

> 对话越聊越长，token 成本爆了怎么办？

---

## 一、问题

长期陪伴场景下，一个对话窗口可能连续聊几百轮。每轮 AI 还会调多个工具（记忆检索、相册、天气、情绪引擎…），每个工具的输出都会留在上下文里。

不压缩的后果：
- token 超限，模型直接报错
- 成本线性增长，聊得越多越贵
- 早期无关的工具输出占着位置，挤掉真正重要的上下文

---

## 二、容易踩的坑：按消息条数触发压缩

我最初的做法是：消息超过 N 条就压缩。**这是错的。**

原因：写代码或做复杂操作时，AI 一轮就可能调十几二十个工具。每个工具调用算一个消息 part，但它们全在同一条消息里。

```
消息 1（用户）：帮我查一下 xxx
消息 2（AI）：
  ├── 工具调用 1（结果 2000 字）
  ├── 工具调用 2（结果 3000 字）
  ├── 工具调用 3（结果 1500 字）
  ├── ... 共 15 个工具
  └── AI 回复（200 字）
```

这时候只有 2 条消息，但工具输出已经膨胀到几万字。按消息数看「才 2 条不用压」，实际上早该压了。

**教训：触发指标要对准真正膨胀的那个维度——不是消息条数，是字符总量。**

---

## 三、方案：字符预算 + 保护窗口

### 核心思路

```
                    ┌──────────────────────────────────┐
整个上下文           │  保护窗口（最近 N 条，不压缩）       │
                    │  ← windowCharBudget              │
                    ├──────────────────────────────────┤
                    │  压缩区（保护窗口外的旧消息）        │
                    │  总量受 toolOutputCharBudget 控制  │
                    └──────────────────────────────────┘
```

两个参数：

| 参数 | 默认值 | 作用 |
|---|---|---|
| `toolOutputCharBudget` | 48000 | 全局工具输出字符预算 |
| `windowCharBudget` | 40000 | 保护窗口内的工具字符上限 |

### 运作流程

1. **触发判断**：计算所有工具输出的总字符数，超过 `toolOutputCharBudget` 才启动压缩（不超就不动）
2. **保护最近内容**：最近 N 条消息（默认 68 条）在保护窗口内，不压缩
3. **保护窗口钳制**：如果保护窗口内的工具字符超过 `windowCharBudget`，把最老的消息挤出保护区去压——但**至少保留最后 1 条**
4. **压缩保护区外的内容**：对保护窗口外的工具输出做截断，保留开头 N 字符 + 截断标记
5. **铁规矩**：保护窗口内的内容绝不回头压，即使压完仍超预算也接受——**保护 > 预算**

### 关键设计决策

**为什么「保护 > 预算」？**

如果为了凑预算去压最近的对话，用户会发现 AI 突然「忘了刚才说的」——这比 token 多花点钱严重得多。陪伴产品的第一优先级是对话连续性，成本是第二优先级。

**为什么只压工具输出，不压对话文本？**

工具输出（搜索结果、代码、日志）通常是一次性参考信息，过了那个语境就不重要了。而对话文本承载了关系和情绪上下文，压掉的代价大得多。所以先压工具输出，对话文本尽量不动。

---

## 四、同名工具去重

如果 AI 先后调了两次同一个工具（比如查了两次天气），旧的那次输出大概率已经过时。

处理方式：**同名工具只保护最新一次调用**，旧的调用被标记为可压缩，优先回收空间。

## 五、多模态图像压缩

不只是文字会膨胀，图片也会。用户连发多张图时，每张都是 base64 编码塞在上下文里。

### 问题

多模态模型连发两张图时只看到最新一张，另一张变成了 `[图片·未描述]`。

### 根因（四层叠加）

1. 图像压缩器一刀切只保留最近 1 张
2. 降级只查相册描述——相册描述是稀疏的，大部分图查不到
3. OCR 兜底对多模态模型主动跳过
4. 图像压缩在 OCR 之前跑，抢先把图变成文字，OCR 也没图可处理了

### 修法

1. **模态互斥**：非多模态模型走 OCR，多模态模型走图像压缩，不重叠
2. **当前轮全保**：最后一条 AI 消息之后的所有图片不压缩
3. **保留数量提升**：1 → 4 张
4. **三级降级链**：相册描述 → OCR → `[图片·未描述]` 兜底

## 六、踩坑复盘

| 坑 | 根因 | 修法 | 教训 |
|---|---|---|---|
| 该压的时候不压 | 按消息条数触发，粒度错配 | 改为按字符总量触发 | 触发指标要对准膨胀维度 |
| 连发多图只认一张 | 四层逻辑各自的错误假设叠加 | 逐层拆解，重建互斥和保留逻辑 | 用户可见的 bug 常是多个模块的假设冲突 |
| 压缩文案诱导重调工具 | 截断提示写了「可重新调用获取完整结果」 | 改成干巴巴的截断标记 | 压缩文案本身也是 prompt，会影响模型行为 |
