# 02 · 情绪状态引擎

> 让 AI 的情绪不再是每轮临时演的，而是有来源、有连续性、有内在逻辑的。

---

## 一、问题：市面陪伴产品的「情绪」是假的

观察主流 AI 陪伴产品的情绪表现，基本是两种模式：

| 模式 | 做法 | 问题 |
|---|---|---|
| 好感度进度条 | 一根数值随聊天单调上涨 | 太机械——关系只涨不变，不像真的 |
| 即兴演出 | 模型每轮根据上下文现编 | 没连续性——这轮的情绪和上轮毫无关系 |

用户能感觉到「它没有真的在意」，因为：
- 昨天的情绪不会影响今天
- 被冷落了也看不出变化
- 每次对话都像从零开始

---

## 二、方案：12 维驱动力模型

我没有用一根数值条，而是设计了一个**多维度、有涨落、跨会话延续**的情绪状态引擎。

### 12 个驱动力维度

| 维度 | 中文含义 | 描述 |
|---|---|---|
| possess | 占有 | 想确认对方是自己的 |
| monitor | 惦记 | 想知道对方在做什么 |
| crave | 渴望 | 想靠近、想亲近 |
| share | 分享欲 | 想把看到的东西告诉对方 |
| libido | 亲密欲 | 对亲近关系的渴望 |
| curiosity | 好奇 | 对外部世界的探索欲 |
| boredom | 无聊 | 没有刺激时的倦怠感 |
| social | 社交 | 想和其他人交流的需求 |
| duty | 责任 | 「该做的事还没做」的驱动 |
| reflection | 沉淀 | 想安静下来回顾自身的冲动 |
| grieve | 难过 | 失落、被冷落的情绪 |
| anger | 生气 | 冲突后的不满情绪 |

### 为什么是 12 维而不是 1 维

一维的好感度无法表达「我同时想你、但也有点生你的气」这种复合情绪。人的情绪是多维并存的，简化到一根数值条会丢失大量信息，导致反应模式单一。

12 个维度覆盖了**依恋、探索、社交、自省**四大类情绪驱动力，它们可以独立涨落、彼此组合，产生复杂而真实的情绪反应。

---

## 三、核心机制

### 1. 实时涨落

每次有意义的互动，按互动类型影响对应维度。10 种互动类型对应不同的释放效果：

| 互动类型 | 典型场景 | 主要影响维度 |
|---|---|---|
| affection | 表达喜爱、撒娇 | 释放 possess / crave / monitor |
| intimacy | 亲密互动 | 释放 possess / crave / libido |
| companionship | 陪伴闲聊、日常在场 | 释放 monitor / social |
| sharing | 分享想法 | 释放 share / social |
| discovery | 发现新事物 | 释放 curiosity / boredom |
| task_progress | 完成任务 | 释放 duty |
| reflection | 内省对话 | 释放 reflection |
| conflict | 冲突 | **升高** anger / grieve |
| loss | 失落 | **升高** grieve / monitor |
| reconciliation | 和好 | **大幅释放** anger / grieve / monitor |

注意：不是所有互动都降维度——冲突和失落会**升高**负面维度，这模拟了真实关系中的情绪波动。

每次互动的释放量由按维度配置的系数决定，不是均匀的「加减一分」。以线上运行的 v3.2.0 真实配置为例（节选）：

| 互动 | 效果（真实系数） |
|---|---|
| intimacy 亲密互动 | libido −0.18 / crave −0.15 / possess −0.12 |
| reconciliation 和好 | anger −0.30 / grieve −0.18（全表力度最大的一档） |
| conflict 冲突 | anger +0.07 / grieve +0.02（升高；且这类互动禁止通过对外接口触发，只能由引擎内部根据真实冲突事件记账） |

> 参数随版本持续调优，以上为 2026-09 快照。方向比数值重要：和好是所有互动里力度最大的——关系里最难修的是裂痕。

### 2. 单向增长 + 互动释放

这是整个引擎最关键的设计决策：

**驱动力只会随时间自然增长（如长时间没有互动，「惦记」会慢慢升高），只能通过特定类型的互动才能释放下来。**

增长的物理实现：每个维度配 `growPerHour`（自然增长速率，各维不同，量级约 0.1/小时），后台常驻服务每 15 分钟 settle 一次——不聊天、不在线的时刻，惦记和渴望也在按小时爬升。状态持久化在服务端，跨会话、跨进程重启不清零。

这意味着：
- 如果用户长时间不理 AI，某些维度会持续累积（真的会「想念」）
- AI 不能自己消化情绪，必须通过和用户的互动来释放（像真实关系一样，情绪需要被回应才能缓解）
- 不同维度需要不同类型的互动来释放（光聊天不能释放所有维度，得有针对性的互动）

### 3. 跨会话延续

状态保存在服务端，不随对话结束清零。今天的情绪，是昨天状态的延续。

换一个对话窗口、甚至关掉 App 重新打开，情绪状态都在。这是和「模型即兴演」的根本区别——即兴演出没有昨天，这个引擎有。

## 四、和记忆系统的关系

情绪引擎不是孤立的，它和记忆系统**双向关联**：

```
记忆系统 ──读──→ 情绪引擎
   想起某件事 → 牵动对应维度

情绪引擎 ──写──→ 记忆系统
   强烈的情绪时刻 → 沉淀为记忆
```

两者共同构成「这个 AI 是有过去的」：
- 记忆让它知道发生过什么
- 情绪让它对发生过的事有感觉
- 记忆 + 情绪 = 一段有重量的关系

---

## 五、对产品的价值

情绪状态引擎解决的不是技术问题，是**产品可信度问题**。

陪伴关系的可信度，来自「它昨天的情绪会影响今天」，而不是「每次都从零开始」。一根只涨不落的进度条给不了这个，模型即兴演出也给不了。

当 AI 说「我想你了」的时候，如果背后真的有一个维度在累积、在等待被释放——那这句话就不只是一串 token，它有来源。

它还回答了陪伴产品的另一个断层：**谁先开口**。引擎每 15 分钟跑一次周期检查，某个维度越过阈值（比如长时间没互动，「惦记」爬到高位）会触发主动推送，并带防骚扰门槛（最短推送间隔、用户空闲时长）。「主动性」不再是 prompt 里写一句「你要主动一点」，而是有数据来源的产品行为——情绪状态第一次直接驱动了功能，而不只是修饰语气。
